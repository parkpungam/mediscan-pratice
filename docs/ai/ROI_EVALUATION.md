## 3. 기준 ROI의 역할과 한계

- 사용자가 표시한 ROI와 비교하는 준비된 기준 영역이다.
- 결과 화면에서 사용자 ROI와 함께 표시해 위치 차이를 이해하게 한다.
- 케이스의 병명, 소견, 용어와 참고자료에 연결한다.
- 기존 공개 데이터셋이 제공한 ROI·라벨을 우선 사용한다.
- 의료전문가 추가 검수 인력이 없으므로 임상적으로 검증된 절대 정답이라고 표현하지 않는다.
- 제품에는 `기준 ROI` 또는 `데이터셋 제공 기준 ROI`라는 표현을 사용한다.

데이터셋 출처, 버전, 라이선스, 원 라벨 생성 과정, 팀의 추가 검수 여부를 함께 기록한다.

## 4. 확정된 평가 흐름

1. 사용자가 정답을 보기 전에 ROI를 표시하고 제출한다.
2. 사용자 ROI를 해당 케이스의 기준 ROI와 비교한다.
3. 위치와 겹침 정도를 반영한다.
4. 정답·부분정답·오답 중 하나를 제공한다.
5. 사용자 ROI와 기준 ROI의 차이 및 해설을 표시한다.
6. 부분정답과 오답을 오답노트에 자동 저장한다.
7. 동일 케이스 재도전과 이전 결과 비교로 연결한다.

ROI 판정은 현재 AI 추론이 아니라 기하학적 위치 비교다. 화면의 `AI 채점` 표현만으로 AI 모델이 평가에 필수라고 해석하지 않는다.

## 5. 부분정답 초기값

산출물 기획서는 기준 ROI와 약 40% 이상 겹치는 경우를 부분정답의 초기값으로 제시한다. 내부기획서는 수치를 고정하지 않으므로 약 40%는 테스트 시작값일 뿐 최종 규칙이 아니다.

- 기능 테스트 결과에 따라 조정할 수 있다.
- 평가 규칙 버전과 함께 기록한다.
- 수치를 바꾸더라도 과거 결과를 재현할 수 있어야 한다.
- 정확한 겹침 지표가 정해지기 전에는 `40%`의 계산 의미도 확정되지 않는다.

## 6. 결정해야 할 형식과 품질 기준

- 기준 형식: 바운딩 박스, 원, 폴리곤, 픽셀 마스크
- 2D 이미지, 3D 볼륨, 슬라이스 묶음의 좌표 표현
- 단일·복수 병변과 병변별 클래스
- 정상·무병변 케이스와 빈 ROI 표현
- 원 데이터셋의 여러 판독자 간 불일치와 합의 정보
- 라벨 버전과 수정 이력

## 7. 결정해야 할 평가 규칙

- 겹침 지표: IoU, Dice, 기준 ROI 대비 포함률 등
- 정답과 부분정답 임계값
- 기준 ROI보다 지나치게 큰 사용자 ROI의 불이익
- 여러 사용자 ROI와 여러 기준 ROI의 매칭
- 일부 병변만 찾은 경우와 오탐을 함께 표시한 경우
- 정상 케이스 또는 ROI 미제출 처리
- 확대·축소·회전·리사이즈 후 좌표 정규화
- 재도전 성공 후 오답노트 완료·숨김과 시도 보존 정책

이 항목은 데이터 분포와 학습 목적을 사용한 기능 테스트 후 [DECISIONS](../project/DECISIONS.md)에서 승인해야 한다.
