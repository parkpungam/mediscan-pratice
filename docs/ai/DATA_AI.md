## 1. 절대 원칙

- 실제 환자 개인정보가 포함된 자료와 비식별화되지 않은 의료데이터를 사용하지 않는다.
- AI 결과는 의료영상 학습을 위한 참고 정보이며 확정적 진단·처방·치료 지시가 아니다.
- 사용자 입력은 별도의 명시적 정책과 승인 없이 모델 재학습에 사용하지 않는다.
- 출처·버전·라이선스·비식별화·라벨 생성 정보가 확인되지 않은 데이터는 제품 케이스나 모델 학습에 사용하지 않는다.
- 의료전문가의 추가 검수가 현재 불가능하다는 사실을 숨기지 않는다.

## 2. 데이터 사용 목적

데이터는 두 목적으로 구분한다.

1. **ROI 판독 훈련:** 영상, 병명 또는 소견, 데이터셋 제공 기준 ROI, 해설, 용어, 참고자료를 케이스로 연결한다.
2. **AI 모델 개발:** 승인된 데이터로 분류·탐지·분할 후보를 학습·검증하고, 사용자 지정 ROI에 학습 참고 결과를 제공한다.

동일 데이터를 두 목적에 함께 사용할 때는 사용자 평가 케이스와 모델 학습·평가 데이터 사이의 누수를 방지해야 한다.

## 3. 데이터 범위

### 확정된 범위

- MVP 신체 부위: 뇌, 흉부, 복부, 무릎
- 실제 환자 개인정보 또는 비식별화되지 않은 데이터: 사용 금지
- 기존 오픈소스 데이터셋 제공 라벨: 우선 활용
- 의료전문가 추가 검수: 현재 불가

### 미확정된 범위

- 부위별 영상 종류와 질환·이상 소견
- 부위별 최소 케이스 수와 우선순위
- 데이터셋 최종 채택
- 분류·탐지·분할 중 부위별 AI 과제
- 목표 약 10,000개 영상의 MVP 적용 여부

내부기획서와 산출물 기획서에는 약 10~15GB가 등장하고, 약 10,000개 영상은 산출물 기획서에만 나온다. 두 수치는 실제 확보·검증 결과에 따라 조정할 목표이지 확정 요구사항이 아니다.

## 5. 포맷과 가공

내부기획서는 원본을 보존하고 웹 조회와 AI 분석 목적에 맞게 변환하는 원칙을 제시한다. 산출물 기획서는 JPG/PNG 영상과 CSV 메타데이터를 더 구체적인 안으로 제시한다.

따라서 다음은 아직 확정하지 않는다.

- 보존할 원본 포맷
- 웹 표시용 파생 포맷
- ROI 라벨 포맷과 좌표계
- 메타데이터 스키마
- DICOM·NIfTI·다중 슬라이스 지원 여부

DICOM이나 NIfTI를 JPG/PNG 한 장으로 무조건 변환하면 정량 정보와 슬라이스 맥락을 잃을 수 있으므로, 데이터셋을 고른 뒤 포맷을 결정한다. 구체 필드는 [DATA_MODEL.md](../system/DATA_MODEL.md)를 따른다.

## 6. 케이스 데이터 품질

ROI 훈련 케이스에는 최소한 다음 정보가 연결되어야 한다.

- 영상 자산과 신체 부위·영상 종류
- 병명 또는 이상 소견
- 데이터셋 제공 기준 ROI
- 주요 영상 소견, 관련 의학용어, 참고자료
- 데이터셋 출처·버전·라이선스
- 원 라벨의 작성·검수 주체와 팀의 추가 검수 여부
- 변환 이력과 좌표계

기준 ROI의 형식, 명칭, 채점, 잠정 40% 값은 [ROI_EVALUATION.md](./ROI_EVALUATION.md)가 담당한다.

## 7. 난이도 추천에 쓰는 데이터

난이도 추천은 의료영상 AI 분석과 별개의 학습 편의 기능이다.

### 확정

- 회원가입에서 학교·교육과정·학년은 수집하지 않는다.
- 전공은 추천 콘텐츠 범위의 가중치로만 사용하며 난이도나 권한을 결정하지 않는다.
- 최초 학습 진입에서 사용자가 학습 경험을 직접 선택한다.
- 경험 선택지는 `처음 학습함`, `기초 이론을 학습함`, `실습 경험이 있음`이다.
- 문제 난이도는 잠정적으로 `입문`, `기초`, `심화`를 사용한다.
- 이후 정답·부분정답·오답과 재도전 이력으로 추천을 조정한다.
- 사용자는 추천과 상관없이 난이도를 직접 변경할 수 있다.
- 추천 규칙과 버전을 기록해 결과를 재현할 수 있어야 한다.

### 미확정

- 학습 경험과 초기 난이도의 연결표
- 추천 갱신 전 최소 풀이 수와 판정별 가중치
- 부위별 이력을 합치는 방식
- 풀이시간 사용 여부와 단계 전환 임계값

## 8. 사용자 영상 AI 분석

### 입력

- 개인정보가 없거나 비식별화된 승인 형식의 의료영상
- 또는 사용자가 확정한 화면 캡처 범위
- 사용자가 지정한 관심 ROI
- 사용자가 명시적으로 선택한 신체 부위 권장

### 기획된 출력

- 선택한 원본 영역
- AI가 탐지한 의심 영역
- 주요 의심 소견
- 후보 질환과 가능성
- 관련 학습 정보

출력은 학습 참고 정보다. 임상 진단, 환자별 의료 조언, 치료 결정을 제공하지 않는다.

뇌·흉부·복부·무릎별 한정 모델 또는 어댑터로 경로를 구분하는 안을 우선 검토한다. 정확한 부위 라우팅, 영상 종류, 질환, 모델 수와 과제 유형은 미확정이다.

사용자 입력을 결과 반환 후 즉시 삭제하는 안이 현재 권장 방향이다. 최종 구현 전 성공·실패·시간초과·취소별 삭제, 임시 파일 수명, 로그·결과 메타데이터 보존 범위를 승인해야 한다.

## 9. AI 모델 평가

### 확정 원칙

- 학습·검증·테스트 데이터를 환자·검사 단위로 분리한다.
- 데이터 중복과 누수를 검사한다.
- 부위·질환·데이터 출처별 성능과 실패 사례를 나눠 본다.
- 모델·데이터·전처리 버전을 결과와 함께 추적한다.
- 공개 데이터셋 라벨 대비 기술 평가를 임상 성능 검증으로 표현하지 않는다.

### 과제별 지표 후보

| 과제 | 지표 후보 | 함께 확인할 항목 |
| --- | --- | --- |
| 분류 | AUROC, 민감도, 특이도, 정밀도, 재현율, F1 | 불균형, 임계값, 확률 보정 |
| 탐지 | mAP, 병변 단위 민감도, 거짓 양성 수, IoU | 작은 병변, 다중 병변 |
| 분할 | Dice, IoU, 경계 오차 | 병변 크기, 빈 마스크 |
| 가능성 표시 | calibration error, Brier score | 점수의 의미와 오해 위험 |

과제와 합격 기준은 데이터셋을 고른 뒤 확정한다. 제품 흐름의 테스트는 [TEST_PLAN.md](../testing/TEST_PLAN.md)가 담당한다.

## 10. 한계와 금지 사항

- 공개 데이터 결과를 실제 임상 성능으로 일반화하지 않는다.
- 특정 국가·학교·직군 연구 결과를 국내 전체 사용자에게 일반화하지 않는다.
- 선택 ROI만 분석한 결과를 전체 영상 진단처럼 표현하지 않는다.
- 후보 질환과 가능성을 확정 질환이나 임상 확률처럼 표시하지 않는다.
- AI 생성 ROI·문제·해설을 사람의 승인 없이 기준 정답으로 게시하지 않는다.
- 전공이나 최초 자기평가만으로 실제 역량을 단정하지 않는다.
- 팀이 붙인 학습 난이도를 임상 증례 난이도나 의료 역량 평가로 표현하지 않는다.

## 11. 구현 전 결정 질문

1. 네 부위별 영상 종류·질환·최소 케이스 수는 무엇인가?
2. 어떤 데이터셋을 채택하며 라이선스·비식별화·라벨 생성 정보는 누가 확인하는가?
3. 의료전문가 추가 검수 부재 위험을 MVP에서 수용하며 어떻게 고지하는가?
4. 사용자 입력 즉시 삭제안을 승인하며 로그와 결과는 무엇을 얼마나 보존하는가?
5. 네 부위별 AI 과제와 모델·어댑터 구성은 무엇인가?
6. `가능성`은 확률·점수·순위 중 무엇이며 낮은 신뢰도는 어떻게 처리하는가?
7. 기술 성능과 사용자 평가의 합격 기준 및 승인 책임자는 누구인가?

모든 미확정 답은 [DECISIONS.md](../project/DECISIONS.md)에 먼저 기록한 뒤 관련 문서에 반영한다.
