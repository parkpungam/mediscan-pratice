> **이 문서가 기준인 내용:** 2단계 회원가입 필드, 버튼 상태, 중복 확인, 동의, 인증메일 안내 상태

## 2. 확정된 화면 흐름

`1/2 계정 정보 → 다음 → 2/2 기본 정보 → 가입하고 인증메일 받기 → 인증메일 발송 안내`

- 2단계에서 `이전`을 누르면 1단계 입력을 화면 메모리에 유지한다.
- 비밀번호와 입력값을 브라우저 영구 저장소에 저장하지 않는다.
- 이번 주에는 실제 계정 저장, 중복 조회, 이메일 발송과 인증 완료를 연결하지 않는다.
- 실제 서버 동작처럼 오해하지 않도록 중복·가입·메일 결과를 시연 상태로 표시한다.

## 3. 1단계 계정 정보

| 항목 | 필수 | 확정 규칙 |
| --- | --- | --- |
| 이메일 | 예 | 로그인 아이디로만 사용하며 실제 서비스에서는 중복 불가 |
| 비밀번호 | 예 | 영문·숫자·특수문자를 포함한 8자 이상 |
| 비밀번호 확인 | 예 | 비밀번호와 동일해야 함 |
| 이용약관 동의 | 예 | 표시 문구: `[필수] 이용약관 동의` |
| 개인정보 동의 | 예 | 표시 문구: `[필수] 개인정보 수집 및 이용동의` |
| 연령 확인 | 예 | `[필수] 만 14세 이상입니다`; 생년월일은 수집하지 않음 |
| 마케팅 이메일 | 아니요 | `[선택] 마케팅 정보 이메일 수신 동의`; 기본 미선택, 거부해도 가입 가능 |

`전체 동의`는 이용약관·개인정보·마케팅 동의를 함께 선택하거나 해제한다. `만 14세 이상입니다`는 약관 동의가 아닌 연령 조건 확인이므로 전체 동의에 포함하지 않고 사용자가 별도로 직접 선택한다. 마케팅 동의를 해제해도 필수 약관과 연령 확인을 마쳤다면 가입할 수 있다.

필수 입력과 필수 확인이 유효해야 `다음` 버튼을 활성화한다. 비밀번호 표시·숨김 기능을 제공한다. 이메일에는 별도 중복 확인 버튼을 두지 않는다. 사용자가 `다음`을 누르면 중복 확인을 수행하고, 중복이면 2단계로 이동하지 않은 채 입력창 아래에 `이미 가입된 이메일입니다.`를 표시한다. 이메일을 수정하면 중복 오류 상태를 초기화한다.

이번 주에는 시연 규칙으로 중복 상태를 보여준다. 향후 백엔드 연결 시 화면과 문구는 유지하고 시연 규칙을 실제 이메일 중복 확인 API 호출로 교체한다. 최종 가입 요청에서도 서버가 중복을 다시 확인해야 한다.

## 4. 2단계 기본 정보

| 항목 | 필수 | 확정 규칙 |
| --- | --- | --- |
| 닉네임 | 예 | 아래 문자·길이 규칙 적용, 중복 불가, 옆에 `중복 확인` 버튼 제공 |
| 전공 | 예 | 승인된 목록에서 선택, 기타 항목은 직접 입력 |
| 가입 경로 | 아니요 | 비워도 가입 가능 |

전공 기본 목록은 다음과 같다.

- 방사선학과
- 의학과/의예과
- 간호학과
- 기타 보건의료계열
- 비전공/해당 없음

닉네임 규칙은 다음과 같다.

- 한글이 한 글자라도 포함되면 전체 2~8자
- 영어·숫자로만 구성되면 전체 4~14자
- 한글·영어·숫자 혼용 가능
- 숫자로만 구성된 닉네임은 불가
- 공백과 특수문자는 불가

가입 경로의 기본 안내 문구는 `메디스캔노트를 알게 된 경로를 선택해 주세요`다. 선택지는 `검색`, `SNS·커뮤니티`, `학교·수업`, `교수·강사`, `친구·지인`, `행사·홍보물`, `기타`다. `기타`를 선택하면 `알게 된 경로를 입력해 주세요` 입력창을 표시하며 이때는 직접 입력이 필요하다. 가입 경로를 선택하지 않은 경우에도 가입할 수 있다.

학교, 교육과정, 현재 학년/상태와 별도 사용자 유형은 수집하지 않는다.

## 5. 닉네임 중복 확인 상태

- 확인 전: 제출할 수 없음
- 사용 가능: 가입 제출 가능
- 이미 사용 중: 오류 표시 후 다른 닉네임 요청
- 확인 완료 후 값 수정: 확인 상태 초기화
- 조회 중·조회 실패: 화면 시연용 상태 제공

이번 주에는 실제 서버 조회를 하지 않는다. 어떤 값을 사용 가능·중복으로 보여줄지는 데모 규칙으로 표시해야 한다.

## 6. 인증메일 발송 안내

- 입력한 이메일 주소를 표시한다.
- `인증메일 다시 보내기`, `이메일 주소 변경`, `로그인으로 이동` 동작을 보여준다.
- 이번 주 화면에서는 실제 이메일을 발송하지 않는다.
- 향후에는 미인증 사용자도 로그인할 수 있지만 인증 관련 동작과 로그아웃 외 핵심 학습 기능은 사용할 수 없다.

실제 인증 토큰, 링크 만료, 재발송 횟수·대기 시간과 메일 서비스는 [DECISIONS](../../project/DECISIONS.md)의 미확정 사항으로 관리한다.

## 8. 구현 전 남은 확인 사항

| 항목 | 현재 상태 | 결정 시점 |
| --- | --- | --- |
| 약관 상세 본문·버전·보기 방식 | 미확정 | 실제 가입·동의 저장 연결 전 |
| 실제 이메일 중복 확인 API | 화면은 확정, 서버 연결 방식은 미구현 | 백엔드 연결 단계 |
| 실제 닉네임 중복 확인 API | 화면은 확정, 서버 연결 방식은 미구현 | 백엔드 연결 단계 |
| 이메일 인증 서비스·링크 정책 | 미확정 | 실제 메일 발송 연결 전 |

프론트엔드는 Vue 3·JavaScript·Vue CLI·Vue Router·Options API·기본 CSS·npm을 사용한다. 회원가입은 `/signup` 경로의 한 화면 안에서 입력 1단계와 2단계, 인증메일 발송 안내 상태를 전환한다. 정확한 패키지 버전은 프로젝트 생성 시 잠금 파일에 기록한다. 화면은 데스크톱 시안을 기준으로 하고 모바일에서도 내용이 겹치거나 화면 밖으로 나가지 않는 기본 반응형을 적용한다. 현재 임시 로고는 공통 로고 영역에서 사용해 나중에 파일만 교체할 수 있게 한다. 전체 기술 상태는 [ARCHITECTURE](../../system/ARCHITECTURE.md)에서 관리한다.
