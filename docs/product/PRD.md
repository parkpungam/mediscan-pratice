# 메디스캔노트 제품 요구사항 정의서(PRD)

> **문서 역할:** MVP의 제품 범위와 검증 가능한 기능·비기능 요구사항을 정의한다.  
> **이 문서가 기준인 내용:** MVP 포함·제외 범위, 요구사항 ID와 우선순위, 제품 수준 완료 조건  
> **이 문서에 기록하지 않는 내용:** 화면별 필드·문구, API 경로, DB 필드, 테스트 절차, 결정 이력  
> **상태:** 사용자 검토 전 기준안  
> **기준일:** 2026-09-11

## 1. 문서 사용 방법

- 프로젝트 배경과 사용자는 [PROJECT_BRIEF](./PROJECT_BRIEF.md)를 따른다.
- 화면 순서는 [USER_FLOW](./USER_FLOW.md), 회원가입 상세는 [SIGN_UP](./features/SIGN_UP.md)을 따른다.
- 시스템 계약은 [ARCHITECTURE](../system/ARCHITECTURE.md), [API](../system/API.md), [DATA_MODEL](../system/DATA_MODEL.md)을 따른다.
- 데이터·AI·ROI 규칙은 [DATA_AI](../ai/DATA_AI.md)와 [ROI_EVALUATION](../ai/ROI_EVALUATION.md)을 따른다.
- 결정 상태는 [DECISIONS](../project/DECISIONS.md), 검증 절차는 [TEST_PLAN](../testing/TEST_PLAN.md)을 따른다.

요구사항 상태는 다음과 같이 구분한다.

- **MUST**: 내부기획서의 MVP 필수 범위
- **조건부**: 핵심 흐름을 위해 필요할 수 있으나 방식 또는 포함 여부가 미확정
- **이후**: Should/Could Have 또는 확장 범위
- **결정 필요**: 요구 의도는 있으나 구현 가능한 기준이 아직 없음

## 2. 제품 원칙

메디스캔노트는 사용자의 의료영상 판단을 대신하지 않는다. 준비된 교육용 케이스에서 사용자가 먼저 판단하고, 기준 ROI와 비교하고, 해설을 학습하고, 오답에 재도전하는 경험이 중심이다. AI는 비식별 사용자 영상의 선택 영역에 대해 의심 소견과 관련 정보를 제시하는 학습 보조 역할만 한다.

## 3. 제안 MVP 범위

내부기획서는 두 핵심 흐름을 모두 Must Have로 정의한다. 따라서 현재 기준 MVP는 다음 두 개의 세로 슬라이스를 포함한다.

### A. ROI 판독 훈련 슬라이스

`케이스 조회/선택 -> 영상 확인 -> 사용자 ROI 표시 -> 제출 -> 기준 ROI 비교 -> 정답/부분정답/오답 및 해설 -> 부분정답·오답 자동 저장 -> 동일 케이스 재도전`

### B. 사용자 의료영상 AI 분석 슬라이스

`비식별 영상 파일 입력 또는 화면 공유 -> 관심 ROI 지정 -> AI 분석 실행 -> 의심 영역·소견·후보 질환·가능성·관련 정보 확인`

### MVP에서 최소화할 항목

- 회원가입은 계정 정보와 기본 정보의 2단계 화면 및 이메일 인증 흐름을 포함한다. 로그인 세션의 실제 구현 방식은 미확정이며 아이디/비밀번호 찾기, 설정, 상세 마이페이지는 제외 제안이다.
- 신체 부위는 뇌, 흉부, 복부, 무릎을 포함한다. 각 부위의 영상 종류·질환·케이스 수는 결정 필요다.
- 대시보드, 상세 취약 영역 추천, 의학용어 사전, 리포트는 별도 화면 대신 결과 해설에 필요한 최소 정보만 제공한다. 최초 학습 경험 선택과 풀이 결과 기반의 최소 난이도 추천은 포함한다.
- DICOM/PACS 전체 기능, 전문 판독보고서 작성, 교수자용 관리 기능은 포함하지 않는다.

## 4. 기능 요구사항

### 4.1 케이스 탐색과 학습 진입

| ID | 상태 | 요구사항 |
| --- | --- | --- |
| TRN-01 | MUST | 서비스는 사전에 준비되고 사용이 허가된 의료영상 학습 케이스를 제공해야 한다. |
| TRN-02 | MUST | 사용자는 학습할 케이스를 선택해 학습 화면으로 진입할 수 있어야 한다. |
| TRN-03 | MUST | 사용자는 뇌, 흉부, 복부, 무릎 중 학습 부위를 선택할 수 있어야 한다. 이후 영상 종류 선택 방식과 부위별 지원 영상 종류는 결정 필요다. |
| TRN-04 | 조건부 | 내부기획서 본문은 케이스 목록 선택 또는 랜덤 시작을 언급하지만 화면 흐름도에는 랜덤 시작이 없다. 랜덤 기능 포함 여부는 결정 필요다. |
| TRN-05 | MUST | 최초 학습 진입 시 사용자는 의료영상 학습 경험을 `처음 학습함·기초 이론을 학습함·실습 경험이 있음` 중에서 선택할 수 있어야 한다. 이 값은 회원가입 항목이 아니다. |
| TRN-06 | MUST | 전공은 추천 콘텐츠의 범위를 조정하는 데만 사용하고 난이도를 직접 결정하지 않아야 한다. 초기 추천 난이도는 사용자가 선택한 학습 경험을 참고하고, 이후 정답·부분정답·오답 및 재도전 이력에 따라 조정한다. 사용자는 추천 난이도를 직접 변경할 수 있어야 한다. |
| TRN-07 | 결정 필요 | 문제 난이도는 우선 `입문·기초·심화`의 잠정 학습 난이도로 관리한다. 단계 전환에 필요한 문제 수·판정 조합, 풀이시간 사용 여부와 임계값은 사용자 테스트 후 확정한다. 이를 임상적 난이도로 표현하지 않는다. |

### 4.2 ROI 문제 풀이

| ID | 상태 | 요구사항 |
| --- | --- | --- |
| ROI-01 | MUST | 사용자는 정답을 보기 전에 의료영상에서 이상하다고 판단한 영역을 ROI로 표시할 수 있어야 한다. |
| ROI-02 | MUST | 사용자는 제출 전에 ROI를 수정·삭제할 수 있어야 한다. |
| ROI-03 | 조건부 | 산출물 기획서와 초기 화면안은 원·박스 ROI와 복수 ROI를 제시한다. 최종 허용 도형과 복수 ROI 처리 규칙은 결정 필요다. |
| ROI-04 | MUST | 제출 시 사용자 ROI를 해당 케이스의 준비된 기준 ROI와 비교해야 한다. |
| ROI-05 | MUST | 비교 결과는 정답·부분정답·오답의 세 상태 중 하나로 제공해야 한다. |
| ROI-06 | 결정 필요 | 겹침 지표, 정답/부분정답 임계값, 다중 병변과 무병변 케이스의 채점 방식은 [ROI_EVALUATION](../ai/ROI_EVALUATION.md)을 따른다. |

### 4.3 결과와 학습 해설

| ID | 상태 | 요구사항 |
| --- | --- | --- |
| FB-01 | MUST | 결과 화면은 사용자가 표시한 ROI와 준비된 기준 ROI를 구분해 보여줘야 한다. |
| FB-02 | MUST | 결과 화면은 정답·부분정답·오답 판정과 위치 차이를 이해할 수 있게 제공해야 한다. |
| FB-03 | MUST | 해설은 준비된 기준 ROI, 병명, 주요 영상 소견, 관련 의학용어, 참고자료를 연결해 제공해야 한다. |
| FB-04 | MUST | 사용자는 결과와 해설을 확인한 뒤 다음 케이스로 이동할 수 있어야 한다. |
| FB-05 | 결정 필요 | 일부 화면에서 "AI 채점·해설"로 표기하지만 최신 본문의 채점은 기준 ROI와의 위치 비교다. AI가 채점 또는 해설 생성에 실제 사용되는지는 미확정이다. |

### 4.5 사용자 의료영상 AI 분석

| ID | 상태 | 요구사항 |
| --- | --- | --- |
| UAI-01 | MUST | 사용자는 개인정보가 없거나 비식별화된 의료영상 파일을 불러오거나 의료영상이 표시된 화면을 공유할 수 있어야 한다. |
| UAI-02 | MUST | 입력 전에 허용 데이터와 개인정보 금지 원칙, 저장 여부와 처리 기준을 고지해야 한다. |
| UAI-03 | MUST | 사용자는 입력 영상에서 분석할 관심 영역을 직접 지정할 수 있어야 한다. |
| UAI-04 | MUST | 사용자가 명시적으로 실행을 요청했을 때 선택 영역을 AI 분석 흐름에 전달해야 한다. |
| UAI-05 | MUST | 결과는 선택한 원본 영역, AI가 탐지한 의심 영역, 주요 의심 소견, 후보 질환과 가능성, 관련 정보를 제공해야 한다. |
| UAI-06 | MUST | 결과를 확정 진단이 아닌 오류 가능성이 있는 의료영상 학습 참고 정보로 명확하게 표시해야 한다. |
| UAI-07 | 결정 필요 | 지원 파일 형식, 최대 크기, 정지영상/연속 프레임 범위와 화면 공유 캡처 방식은 미확정이다. 입력 영상은 분석 직후 삭제하는 방안을 우선 권장하되 최종 승인과 실패·타임아웃 시 삭제 기준이 필요하다. |
| UAI-08 | 결정 필요 | AI 결과를 오답노트나 학습 이력과 연결할지는 원본에 정의되어 있지 않다. |
| UAI-09 | 결정 필요 | 뇌·흉부·복부·무릎별 한정 모델 또는 어댑터와 사용자의 명시적 부위 선택을 우선 권장한다. 실제 모델 수, 라우팅, 과제와 지원 질환은 승인 전까지 미확정이다. |

| ACC-09 | 제외 | 학교·교육과정·현재 학년/상태는 MVP 회원가입과 프로필에서 수집하지 않는다. 향후 실제 기능 목적이 생기기 전까지 다시 추가하지 않는다. |
| ACC-10 | MUST | 닉네임은 별도 중복 확인 후 제출할 수 있고, 값을 수정하면 확인 상태를 초기화해야 한다. |
| ACC-11 | MUST | MVP 가입 대상은 만 14세 이상으로 제한하고 만 14세 미만 가입 및 법정대리인 동의 흐름은 제공하지 않는다. |
| ACC-12 | MUST | 화면단은 성공·오류·로딩 상태를 시연하되 실제 서버 동작으로 오인되지 않아야 하고 계정 정보를 영구 저장하지 않아야 한다. |
| ACC-13 | MUST | 가입 경로는 선택 항목이며 정확한 라벨과 안내 문구는 [SIGN_UP](./features/SIGN_UP.md)을 따른다. |

## 5. 데이터 요구사항

- 케이스는 영상, 분류, 기준 ROI, 해설과 출처 정보를 연결해야 한다.
- 사용자 시도와 재도전은 이전 결과를 재현하고 비교할 수 있어야 한다.
- 공개 데이터의 허용 목적·비식별화·라벨 출처와 변환 이력을 추적해야 한다.
- 비밀번호 원문과 사용자 의료영상 바이너리를 관계형 DB에 저장하지 않는다.
- 구체 엔터티와 필드는 [DATA_MODEL](../system/DATA_MODEL.md), 데이터셋과 AI 규칙은 [DATA_AI](../ai/DATA_AI.md), 기준 ROI는 [ROI_EVALUATION](../ai/ROI_EVALUATION.md)을 따른다.

## 6. 비기능 요구사항

### 6.1 안전과 개인정보

- 실제 환자 개인정보 및 비식별화되지 않은 의료데이터를 처리하지 않는다.
- 닉네임은 실명 노출을 줄이지만 계정과 연결되면 개인정보다. 이메일, 닉네임, 전공, 가입 경로, 동의 기록, 접속 기록, 의료영상 학습 경험, 난이도 선택, 사용자별 ROI 시도·오답·학습 이력을 개인정보로 취급하고 필요한 최소 범위만 수집한다.
- 학교·교육과정·현재 학년/상태는 수집하지 않는다. 전공과 학습 경험은 각각 콘텐츠 범위 및 초기 난이도 추천이라는 고지된 목적에만 사용한다.
- 사용자에게 허용 입력과 금지 입력을 분석 전에 명확하게 안내한다.
- AI 결과의 비진단성과 오류 가능성을 결과 확인 전에 식별 가능하게 표시한다.
- 전송, 보관, 삭제, 로그 정책은 개발 착수 전에 승인되어야 한다.
- 이메일 미인증 상태의 핵심 기능 차단은 클라이언트 화면에만 의존하지 않고 모든 보호 API에서 동일하게 강제해야 한다.

### 6.2 데이터 품질과 추적성

- 영상과 라벨의 일치 여부를 확인할 수 있어야 한다.
- 학습·검증·테스트 데이터를 분리하고 데이터 누수를 방지해야 한다.
- 기준 ROI와 해설의 작성·검수 출처를 추적할 수 있어야 한다.
- 의료전문가 검수가 없는 데이터셋 제공 라벨을 임상적으로 검증된 정답처럼 표현하지 않아야 한다.
- 데이터셋별 라이선스와 허용 이용 범위를 기록해야 한다.

### 6.3 사용성

- PC 웹 환경에서 핵심 두 흐름을 완료할 수 있어야 한다.
- ROI 입력과 기준 ROI는 시각적으로 구분되어야 한다.
- 사용자가 정답을 보기 전에 답안을 제출하는 순서가 유지되어야 한다.
- 성능, 접근성, 브라우저 지원 범위와 정량 사용성 목표는 미확정이다.

### 6.4 AI 품질

- 모델은 별도 검증·테스트 데이터로 평가하고 부위·질환별 오류와 한계를 기록해야 한다.
- 지원하지 않는 영상, 낮은 품질, 불확실한 결과를 다루는 UI와 기준이 필요하다.
- 과제별 지표와 합격 기준은 모델 유형 선정 후 확정한다.

### 6.5 운영

- 산출물 기획서는 HTTPS 적용과 클라우드 배포를 제안하지만 구체 인프라는 미확정이다.
- 감사 로그, 모니터링, 장애 목표, 백업·복구, 비용 한도는 아직 요구사항이 없다.

## 7. MVP 제외 범위

다음은 내부기획서에서 Should/Could Have이거나 확장 범위로 제시된 기능이다.

- 상세 학습 대시보드, 진도율·정답률·완료 케이스 통계
- 상세 취약 영역 분석, 대시보드형 맞춤 케이스 추천. 최초 학습 경험과 풀이 결과에 따른 최소 난이도 추천은 포함
- 학교·교육과정·현재 학년/상태 수집과 학교별 추천
- AI 문제 자동 생성 및 자동 기준 ROI·해설 생성
- 직군별 해설과 정보 분기
- 독립 의학용어 사전과 판독 보조 기능
- 기간별 리포트
- 교수자용 학습 현황, 증례 등록, 평가 관리와 관리자 페이지
- 교육기관 B2B/B2B2C 운영 기능
- 전문 수련 의료인을 위한 고급 판독·보고서 작성 기능
- 완전한 DICOM/PACS 관리·공유 기능
- 상용화, 결제, 수익화 기능

## 8. 시나리오 단위 완료 조건

### ROI 판독 훈련

최초 학습 사용자가 자신의 학습 경험을 선택하고 추천 난이도를 확인하거나 직접 변경한 뒤 승인된 케이스를 선택할 수 있어야 한다. ROI를 제출하면 기준 ROI와의 비교 판정과 다섯 가지 해설 정보를 확인할 수 있어야 한다. 오답과 부분정답은 자동으로 오답노트와 다음 난이도 추천에 반영되고, 같은 케이스 재도전 후 이전 결과와 새 결과를 비교할 수 있어야 한다.

### 사용자 영상 AI 분석

사용자가 개인정보 금지와 처리 정책을 확인하고 허용된 영상을 입력한 뒤 관심 영역을 지정해 분석을 실행할 수 있어야 한다. 결과에는 정의된 다섯 항목과 비진단성 안내가 함께 표시되어야 한다.

### 데이터 안전

테스트와 데모에서 사용된 모든 영상은 출처·라이선스·비식별화 상태가 확인되어야 하며, 실제 환자 개인정보가 포함된 자료가 저장소와 서비스에 존재하지 않아야 한다.
