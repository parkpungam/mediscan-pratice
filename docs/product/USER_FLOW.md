# 메디스캔노트 사용자 흐름

> **문서 역할:** 사용자가 서비스에서 이동하고 행동하는 순서와 예외 흐름을 정의한다.  
> **이 문서가 기준인 내용:** 화면 전이, 사용자 행동 순서, 핵심 여정과 예외 상태  
> **이 문서에 기록하지 않는 내용:** 입력 필드 상세, 제품 우선순위, API·DB·평가 공식  
> **상태:** 내부기획서 최신 흐름 기준 / 일부 전이 미확정  
> **기준일:** 2026-09-11

## 1. 문서 사용 방법

- 제품 포함 범위는 [PRD](./PRD.md)를 따른다.
- 회원가입 필드·검증·문구는 [SIGN_UP](./features/SIGN_UP.md)을 따른다.
- 기준 ROI 판정은 [ROI_EVALUATION](../ai/ROI_EVALUATION.md)을 따른다.
- 확정·충돌 상태는 [DECISIONS](../project/DECISIONS.md)을 따른다.
- 우선 원본은 `references/notion/메디스캔노트_화면흐름도.png`이며, 자료 차이는 이 문서의 8절에 기록한다.

## 2. 전체 구조

메디스캔노트에는 두 개의 핵심 사용자 여정과 이를 지지하는 오답 재학습 여정이 있다.

1. **ROI 판독 훈련**: 준비된 케이스에서 사용자가 직접 판단하고 기준 ROI와 비교한다.
2. **오답 재학습**: 틀린 케이스를 모아 동일한 문제에 다시 도전하고 이전 결과와 비교한다.
3. **사용자 영상 AI 분석**: 비식별 사용자 영상의 관심 영역을 지정해 학습 참고용 분석 정보를 확인한다.

계정, 대시보드, 의학용어 사전, 통계, 리포트는 주변 기능이다. 최신 화면 구성에는 포함되지만 모두 MVP 필수로 확정된 것은 아니다.

## 3. 진입 및 계정 흐름

### 자료에 나타난 흐름

`시작 -> 홈/메인 -> 로그인 -> 성공 시 로그인 완료/메인 -> 기능 선택`

미가입자는 다음 흐름을 사용한다.

`회원가입 1단계 계정 정보 -> 회원가입 2단계 기본 정보 -> 가입 제출 -> 인증 메일 발송 안내 -> 로그인 -> 미인증 제한 화면 -> 이메일 인증 완료 -> 핵심 기능 활성화`

1단계는 계정 정보와 동의, 2단계는 기본 정보를 입력한다. 정확한 필드, 검증, 버튼 상태와 시안은 [SIGN_UP](./features/SIGN_UP.md)을 기준으로 한다.

로그인 화면에서 아이디/비밀번호 찾기로 이동하는 보조 경로도 제시되어 있다.

이메일 미인증 사용자도 로그인은 할 수 있다. 로그인 후에는 인증 필요 안내와 인증 메일 재발송·이메일 주소 변경·로그아웃만 제공하고, 케이스 학습·ROI 제출·결과/오답노트·AI 분석 등 핵심 기능으로 이동하면 인증 필요 화면으로 전환한다. 이메일 인증을 완료한 뒤 새로고침하거나 세션 상태를 다시 확인하면 핵심 기능을 활성화한다.

이번 주 화면 산출물과 실제 백엔드 연결 시점은 [IMPLEMENTATION_PLAN](../project/IMPLEMENTATION_PLAN.md)에서 관리한다.

### 미확정 사항

- 내부기획서의 화면 목록은 회원가입, 직군·기본정보, 로그인, 찾기, 마이페이지, 설정을 포함한다. 현재 사용자 결정은 직군·학교·교육과정·현재 학년/상태 대신 전공만 필수로 받는 방식이다.
- 최신 첨부 흐름도는 회원가입 후 로그인으로 이동하는 구조를 보여준다.
- `서비스유저플로우.png`(작업 시작 시 파일명 `시스템아키텍처.png`)의 초기 화면안은 앱 시작 시 메인이 먼저 보이고 메인에서 로그인하는 흐름을 제시한다.
- 비로그인 상태에서 케이스 탐색 또는 AI 분석을 허용할지는 정의되어 있지 않다.
- MVP에 계정 복구와 설정까지 포함할지는 결정이 필요하다.
- 향후 백엔드 연결 시 인증 링크 만료 시간과 재발송 횟수·대기 시간은 결정이 필요하다.
- 가입 후 닉네임 변경 가능 여부는 결정이 필요하다.

## 4. 핵심 시나리오 A - ROI 판독 훈련

### 사용자 목적

준비된 의료영상에서 이상 부위를 스스로 찾고, 자신의 위치 판단을 기준 ROI와 비교해 해설을 학습한다.

### 기본 흐름

1. 사용자가 메인 또는 학습 대시보드에서 **학습 시작**을 선택한다.
2. 최초 진입이라면 의료영상 학습 경험을 `처음 학습함`, `기초 이론을 학습함`, `실습 경험이 있음` 중에서 선택한다.
3. 시스템이 선택한 학습 경험을 참고해 초기 난이도를 추천한다. 사용자는 `입문`, `기초`, `심화` 중 다른 난이도로 직접 변경할 수 있다.
4. 학습할 **신체 부위**를 뇌, 흉부, 복부, 무릎 중에서 선택한다. 전공은 추천 콘텐츠 범위의 가중치로만 사용하며 다른 부위의 학습을 제한하지 않는다.
5. **영상 종류**를 선택한다.
6. 조건에 맞는 **케이스 목록**에서 문제를 선택한다.
7. 의료영상 학습 화면에서 정답을 보지 않고 영상을 확인한다.
8. 이상하다고 판단한 부위를 ROI로 표시한다.
9. 필요하면 ROI를 수정하거나 삭제하고 답안을 제출한다.
10. 시스템이 사용자 ROI와 준비된 기준 ROI의 위치·겹침을 비교한다.
11. 사용자는 정답·부분정답·오답 판정과 두 ROI의 차이를 확인한다.
12. 기준 ROI, 병명, 주요 영상 소견, 관련 의학용어, 참고자료를 확인한다.
13. 정답 또는 학습 완료 후 다음 케이스로 이동할 수 있다.
14. 부분정답과 오답은 오답노트에 자동 반영되고 이후 난이도 추천 조정에 활용된다.

### 대체·예외 흐름

- 내부기획서 본문은 케이스를 직접 고르거나 랜덤으로 시작할 수 있다고 쓰지만 흐름도에는 랜덤 경로가 없다.
- ROI가 없거나 허용 형식이 아니거나 제출 조건을 충족하지 못한 경우의 메시지는 정의되어 있지 않다.
- 정상 케이스, 다중 병변, 여러 ROI의 처리와 부분정답 직후 재도전·다음 케이스 선택 방식은 정의되어 있지 않다.
- 참고자료를 본 뒤 원래 결과 화면으로 돌아오는 상세 전이는 정의되어 있지 않다.

## 5. 핵심 시나리오 B - 오답노트와 재도전

### 사용자 목적

이전에 잘못 판단한 케이스를 다시 풀고 이전 시도와 비교해 취약 영역을 보완한다.

### 기본 흐름

1. 부분정답 또는 오답으로 판정된 케이스가 오답노트에 자동 저장된다.
2. 사용자가 메인, 마이페이지 또는 결과 화면에서 오답노트로 진입한다. 정확한 진입 위치는 화면 자료마다 다르다.
3. 오답 목록에서 복습할 케이스를 선택한다.
4. 오답 상세에서 이전 판정과 케이스 정보를 확인한다.
5. **다시 풀기**를 선택한다.
6. 동일한 의료영상에서 기준 ROI를 보지 않고 새 ROI를 표시하고 제출한다.
7. 새 결과와 해설을 확인한다.
8. 이전 ROI·판정과 새 ROI·판정을 비교해 변화와 남은 오류를 확인한다.
9. 정책에 따라 오답 상태를 유지하거나 완료 처리한다.

### 연결 상태

이 흐름은 단순한 저장 목록이 아니라 다음 순환을 보장해야 한다.

`ROI 문제 풀이 -> 기준 ROI 비교 -> 결과 피드백 -> 부분정답·오답 자동 저장 -> 동일 케이스 재도전 -> 이전 결과 비교 -> 추가 재학습 또는 완료`

### 미확정 사항

- 정답으로 개선되면 항목을 제거할지, 완료 상태로 남길지 정의되어 있지 않다.
- 이전 ROI와 결과를 몇 회까지 보존하고 어떤 방식으로 비교할지 정의되어 있지 않다.

## 6. 핵심 시나리오 C - 사용자 의료영상 AI 분석

### 사용자 목적

준비된 학습 케이스 외에 별도로 접한 비식별 의료영상의 관심 영역에 관한 의심 소견과 관련 정보를 학습 참고자료로 확인한다.

### 기본 흐름

1. 사용자가 메인에서 **AI 영상 분석**에 진입한다.
2. 서비스가 개인정보가 없거나 비식별화된 영상만 허용한다는 점과 저장·처리 정책을 안내한다.
3. 사용자가 의료영상 파일을 불러오거나 의료영상이 표시된 화면을 공유한다.
4. 입력 영상에서 분석하려는 관심 영역을 직접 지정한다.
5. 사용자가 AI 분석 실행을 요청한다.
6. 서비스가 선택 영역을 분석 모듈에 전달한다.
7. 사용자는 다음 결과를 확인한다.
   - 선택한 원본 영역
   - AI가 탐지한 의심 영역
   - 주요 의심 소견
   - 후보 질환과 가능성
   - 관련 정보
8. 결과 화면은 해당 결과가 확정 진단이 아니라 의료영상 학습을 위한 참고 정보임을 표시한다.
9. 분석에 사용한 업로드·캡처 영상은 결과 반환 후 즉시 삭제하는 방향을 권장한다. 이 항목은 사용자 답변이 잠정 표현이므로 성공·실패·시간초과·취소별 삭제 시점과 결과 메타데이터 보존 범위를 승인받기 전에는 확정 정책으로 보지 않는다.

### 예외 흐름 - 정의 필요

- 개인정보 또는 번인 정보가 감지되었을 때의 차단 방식
- 미지원 파일·부위·영상 종류, 손상 파일, 낮은 화질 처리
- 화면 공유 취소, 권한 거부, 캡처 대상 변경
- 관심 ROI가 없거나 너무 작거나 여러 개인 경우
- 모델 불확실성이 높거나 결과가 없을 경우
- 업로드·캡처 데이터의 성공·실패·시간초과·취소별 삭제 보장과 분석 결과 메타데이터 보존 여부

2026-09-10에 추가된 시퀀스 다이어그램은 구현 초안이다. 현재 확정안과 다른 회원가입 정보, 계정 식별 방식, ROI 판정, AI 모델명이 포함되어 있으므로 직접 기준으로 사용하지 않는다. 항목별 차이는 [DECISIONS의 C-015~C-019](../project/DECISIONS.md#6-자료-간-충돌모호성-기록)을 따른다.

## 9. 화면 설계 전 결정할 질문

- 최소 MVP에서 로그인 없이 체험을 허용할 것인가?
