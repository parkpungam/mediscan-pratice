# 메디스캔노트 아키텍처 기준안

> **문서 역할:** 프론트엔드, 백엔드, 데이터베이스, 스토리지와 AI의 책임·경계를 정의한다.  
> **이 문서가 기준인 내용:** 논리 구성, 구성요소 책임, 데이터 흐름, 기술 후보와 배포 결정  
> **이 문서에 기록하지 않는 내용:** API 경로, 엔터티 필드, 제품 화면 규칙, AI 평가 공식  
> **상태:** 논리 구조 기준안 / 프론트엔드 기술 확정, 나머지 기술 미확정  
> **기준일:** 2026-09-14

## 2. 원본에서 확인된 기술 후보

내부기획서의 기술 섹션은 "추후 확정 후 수정"으로 표시되어 있다. 산출물 기획서는 제출용 문서로 더 구체적인 배포안을 제안하지만, 제품 기획 판단은 내부기획서를 기준으로 한다. 사용자 승인에 따라 웹 프론트엔드는 Vue 3·JavaScript·Vue CLI·Vue Router·Options API·기본 CSS·npm으로 확정했으며 나머지는 승인 전까지 후보로 둔다.

| 계층 | 후보 | 원본의 역할 | 상태 |
| --- | --- | --- | --- |
| 웹 프론트엔드 | Vue 3, JavaScript, Vue CLI, Vue Router, Options API, 기본 CSS, npm | 의료영상 조회, ROI 표시, 사용자 상호작용 | 확정. 패키지의 정확한 버전은 프로젝트 생성 시 잠금 파일에 기록 |
| 서비스 API | FastAPI | 케이스 조회, ROI 평가, 해설, 오답, AI 분석 요청 | 미확정 |
| 관계형 데이터베이스 | PostgreSQL | 사용자, 케이스, 기준 ROI, 평가, 해설, 오답 | 미확정 |
| 프론트 호스팅 | Cloudflare Pages | 정적 웹 배포, 도메인, HTTPS | 산출물 기획서 제안, 미확정 |
| API·AI·DB 운영 | AWS | 백엔드, AI 분석 서버, DB 운영 | 서비스 구성 미확정 |

| AI 모델·프레임워크 | 미선정 | 데이터 특성·성능 검토 후 선정 | 미확정 |
| 객체 스토리지 | 제품 미지정 | 의료영상과 파생 산출물 저장 필요 가능성 | 미확정 |

## 3. 논리 구성

아래는 특정 제품을 확정하지 않은 논리 구조다.

```text
[사용자 PC 웹 브라우저]
  - 케이스 탐색/의료영상 표시
  - ROI 작성·수정·삭제
  - 오답 재도전/결과 비교
  - 비식별 영상 선택 또는 화면 공유
  - AI 결과와 비진단성 안내 표시
                  |
                  v
[서비스 API 경계]
  - 인증·사용자(포함 여부 미확정)
  - 케이스·해설 조회
  - ROI 제출·위치 기반 평가
  - 시도 이력·오답노트
  - 사용자 영상 정책 확인·AI 요청 조정
          |                 |
          v                 v
[관계형 데이터]       [AI 분석 서비스]
  - 메타데이터          - 입력 검증/전처리
  - 기준 ROI            - 선택 ROI 분석
  - 평가/시도           - 의심 영역·소견·후보 정보
  - 오답 상태            - 불확실성/한계 반환
          |
          v
[의료영상/파생파일 스토리지]
  - 공개 사용이 허가되고 비식별화된 학습 케이스
  - 사용자 입력은 보관 정책 확정 전 영구 저장 금지
```

`관계형 데이터`와 `파일 스토리지`의 실제 제품, AI 서비스의 프로세스·서버 분리, API의 배포 단위는 미확정이다.

## 4. 구성요소별 책임

### 4.1 프론트엔드

확인된 책임은 다음과 같다.

- PC 웹에서 케이스, 의료영상, 해설, 오답과 분석 결과 표시
- 2단계 회원가입 폼, 단계 간 입력 유지, 이메일·비밀번호·닉네임 검증, 약관·만 14세 이상 동의와 이메일 인증 상태 표시
- 전공 선택·기타 직접 입력·비전공/해당 없음 상태. 학교·교육과정·현재 학년/상태는 입력받지 않음
- 이메일 미인증 상태에서도 로그인 화면을 통과시키되 핵심 기능 대신 인증 필요 화면을 표시하고 재발송·이메일 변경·로그아웃 동작 제공
- 최초 학습 진입 시 학습 경험 선택, 추천 난이도 표시와 사용자 직접 변경
- 사용자 ROI 생성·수정·삭제와 제출
- 사용자 ROI와 기준 ROI의 시각적 구분
- 파일 선택 또는 브라우저 화면 공유, 분석 ROI 선택, 명시적 분석 실행
- 개인정보 금지·처리 정책·AI 비진단성 고지
- 오답 선택, 동일 케이스 재도전, 이전 결과 비교
- 2026년 10월 1~2일 중간발표에 앞서 이번 주에는 2단계 회원가입 프론트엔드와 인증메일 발송 안내 상태만 구성한다. 실제 계정·동의 저장, 중복 판정, 이메일 발송·인증은 이후 백엔드 단계에서 연결

미확정 항목은 뷰어 라이브러리, DICOM 지원, 영상 확대·윈도/레벨 조정, 브라우저 지원 범위, 캔버스 좌표 표준화 방식이다.

### 4.2 백엔드/API

확인된 논리 책임은 다음과 같다.

- 케이스와 해설 메타데이터 조회
- 사용자 ROI 수신과 기준 ROI 비교
- 정답·부분정답·오답 판정 반환
- 사용자 시도와 오답노트 저장 및 재도전 이력 조회
- 전공은 콘텐츠 범위, 최초 학습 경험과 풀이 결과는 난이도에 사용하는 버전형 규칙 기반 추천. 구체 전환 규칙은 미확정
- 사용자 영상 입력 정책 확인과 AI 분석 서비스 호출 조정
- AI 결과를 교육용 응답 형식으로 반환
- 인증 세션과 이메일 인증 상태를 구분하고, 미인증 세션의 케이스 학습·ROI·오답노트·AI 분석 API 접근을 공통 권한 검사에서 거부

인증·세션의 구체 기술, 관리자 API, 비동기 작업 큐, 캐시, API 버전 방식은 미확정이다. 이메일 미인증 세션의 제한 정책 자체는 확정됐으며 프론트엔드 화면 숨김만으로 대체할 수 없다.

### 4.3 데이터베이스

관계형 데이터 영역은 사용자·동의, 학습 설정, 케이스·기준 ROI·해설, 시도·오답, 모델·평가 버전이다. 대용량 의료영상 바이너리와 사용자 원본 영상은 관계형 DB에 저장하지 않는다.

엔터티와 주요 필드의 기준 위치는 [DATA_MODEL](./DATA_MODEL.md)이다. 이 문서에는 데이터베이스가 맡는 책임과 다른 저장소와의 경계만 기록한다.

### 4.4 의료영상·파일 스토리지

관계형 DB 외에 용량이 큰 의료영상과 파생 이미지를 저장할 계층이 필요할 가능성이 높지만 원본은 제품을 지정하지 않는다.

다음 영역을 분리해 설계해야 한다.

- 승인된 공개 교육·연구용 원본 데이터
- 웹 조회용 변환본
- 기준 ROI 및 라벨 파일
- 모델 학습·검증·테스트 데이터 분할
- 사용자 입력 영상 또는 선택 영역 - 분석 처리 중 격리된 임시 영역에만 두고 결과 반환 후 즉시 삭제하는 방향을 권장하되 최종 정책 승인 필요
- 모델 산출물과 버전 정보 - 저장 범위 미확정

스토리지 제품, 암호화, 수명주기, 백업, 접근권한은 개발 전 결정이 필요하다.

### 4.5 AI 분석 서비스

AI 분석 서비스는 두 제품 기능과 구분한다.

1. **ROI 판독 훈련 채점**: 현재 기준은 AI 추론이 아니라 준비된 기준 ROI와의 위치·겹침 비교다. UI의 "AI 채점" 표현은 실제 구현 역할과 일치하도록 정리해야 한다.
2. **사용자 영상 AI 분석**: 사용자가 지정한 관심 영역을 모델에 전달해 의심 영역, 주요 의심 소견, 후보 질환과 가능성, 관련 정보를 반환한다.

뇌·흉부·복부·무릎별 한정 모델 또는 어댑터로 요청을 분리하는 구조를 우선 권장한다. 사용자가 부위를 명시적으로 선택하거나 검증 가능한 라우터가 지원 범위를 확인해야 하며, 영상만 보고 부위를 추정해 임의 라우팅하지 않는다. 모델이 분류, 탐지, 분할 중 무엇을 수행할지와 실제 모델 수·프레임워크는 데이터와 검증 결과를 보고 결정한다.

## 5. 핵심 데이터 흐름

### 5.1 ROI 판독 훈련

1. 프론트엔드가 현재 사용자의 학습 경험 설정과 추천 난이도 상태를 조회한다.
2. 최초 학습이면 사용자가 학습 경험을 선택하고, 프론트엔드는 서버가 계산한 초기 추천 난이도와 직접 변경 옵션을 표시한다.
3. 프론트엔드가 선택 난이도·부위·영상 종류에 맞는 케이스와 영상 접근 정보를 가져온다. 전공은 콘텐츠 추천 가중치일 뿐 접근 제한으로 사용하지 않는다.
4. 사용자가 이미지 표시 좌표계에서 ROI를 작성한다.
5. 프론트엔드는 ROI와 케이스 식별자를 API에 제출한다.
6. 백엔드는 좌표를 정규화하고 준비된 기준 ROI와 승인된 지표로 비교한다.
7. 백엔드는 판정, 비교에 필요한 ROI, 해설을 반환한다.
8. 부분정답 또는 오답이면 시도와 오답노트 항목을 자동 연결하고, 승인된 규칙 버전으로 다음 난이도 추천을 갱신한다.
9. 재도전 시 새 시도를 만들고 이전 시도와 비교 가능한 형태로 반환한다.

정규화 좌표 규격, 평가 지표와 임계값은 미확정이다.

### 5.2 사용자 의료영상 AI 분석

1. 프론트엔드가 허용 데이터와 저장·처리 정책을 먼저 표시한다.
2. 사용자가 파일을 선택하거나 브라우저 화면 공유 권한을 부여한다.
3. 사용자가 관심 영역을 지정하고 분석을 실행한다.
4. 승인된 입력 범위만 API 또는 AI 서비스로 전송한다.
5. AI 서비스가 전처리, 추론, 후처리를 수행한다.
6. API가 결과 형식과 비진단성 안내를 함께 프론트엔드에 반환한다.
7. 프론트엔드는 선택한 원본 영역과 의심 영역을 구분해 표시한다.
8. 권장안에 따라 결과 반환 직후 입력 영상과 선택 영역 파일을 삭제한다. 실패·시간초과·취소·작업자 비정상 종료에서도 삭제되도록 수명주기 정리 작업을 둔다. 결과 메타데이터와 로그의 최소 보존 범위는 별도 승인 대상이다.

화면 전체 프레임을 지속 전송할지, 사용자가 확정한 정지 이미지/ROI만 전송할지는 반드시 개발 전에 결정한다. 사용자 입력 즉시 삭제 방침도 사용자 답변이 잠정적이므로 최종 승인 전에는 구현 계약으로 고정하지 않는다.

## 6. 개인정보·안전 경계

- 닉네임을 사용해 공개 화면의 실명 노출을 줄여도 계정은 익명 계정이 아니다. 이메일, 닉네임, 전공, 가입 경로, 학습 경험·난이도 선택, 동의·접속 기록, 계정별 학습·오답 이력을 개인정보 경계 안에서 처리한다.
- 학교·교육과정·현재 학년/상태는 현재 데이터 모델과 API에서 수집하지 않는다. 전공과 학습 경험은 각각 고지된 콘텐츠·난이도 추천 목적을 벗어나 사용하지 않는다.
- MVP는 만 14세 미만 가입을 제공하지 않는다. 생년월일을 기본 수집하지 않고 만 14세 이상 자기확인 값을 기록하는 안을 사용하되 실제 공개 운영 전 문구와 확인 수준을 검토한다.
- 실제 환자 개인정보와 비식별화되지 않은 의료데이터는 시스템 경계 안으로 들어오면 안 된다.
- 업로드와 화면 공유는 개인정보 금지 고지에 동의한 뒤에만 활성화해야 한다.
- 클라이언트 검사만으로 비식별화를 보장한다고 간주하지 않는다. 자동 검사, 서버 검증, 사람 검수의 필요 수준은 결정이 필요하다.
- 원본·변환본·ROI·로그·백업의 보관 위치와 삭제 시점을 한 정책으로 추적해야 한다.
- AI 출력은 의료 진단으로 소비되지 않도록 응답 스키마와 화면 문구에서 역할을 제한한다.
- 학습 케이스의 기준 ROI와 라벨은 기존 공개 데이터셋 제공값을 우선 사용한다. 의료전문가 검수 인력이 없으므로 이를 임상적으로 검증된 정답이라고 표시하지 않고 출처·버전·검수 수준을 함께 기록한다.
- HTTPS는 산출물 기획서가 제안한 요구이며, 실제 전송 보안과 저장 암호화 기준은 보안 결정으로 별도 확정해야 한다.

## 7. 원본별 아키텍처 기술 차이

| 항목 | 내부기획서 | 산출물 기획서 | 화면 자료 | 처리 |
| --- | --- | --- | --- | --- |
| 기술 확정도 | 추후 확정이라고 명시 | 구체 배포안 제시 | 기술 구조 없음 | 전체 후보로 유지 |
| Cloudflare 역할 | 화면 공유 데이터 중계로 설명 | Pages 프론트 배포·도메인·HTTPS | 없음 | 중계 여부 결정 필요 |
| 화면 공유 전송 | Cloudflare 중계 시사 | 선택 영역 이미지를 FastAPI API로 전달 | 사용자 단계만 표시 | 데이터 경로 결정 필요 |
| AI 모델 | 미선정 | 미선정 | 초기 구성은 MedGemma·출혈 확률 언급 | 초기 모델 문구는 폐기/검토 대상 |
| 아키텍처 이미지 | 예시 `image.png`는 의도적으로 제외됨 | 별도 다이어그램 없음 | 별도 파일의 실제 내용은 화면 구성 | 누락·충돌이 아니며 현재 문서의 논리 구조를 기준안으로 사용 |

## 8. 배포 전 결정 목록

- FastAPI와 PostgreSQL을 최종 채택할지
- Cloudflare Pages와 AWS를 사용할지, 각각 어떤 책임을 맡을지
- 의료영상과 모델 파일용 객체 스토리지 및 리전
- 브라우저-API-AI 사이의 화면 공유·선택 이미지 전송 경로
- 동기/비동기 추론, 타임아웃, 작업 상태 전달 방식
- 인증, 권한, 세션, 비밀 관리 방식
- 사용자 입력, 결과, 로그, 백업의 보존·삭제 정책
- 전송·저장 암호화, 감사 기록, 모니터링, 복구 목표
- 개발·검증·운영 데이터와 모델 환경의 분리 기준
