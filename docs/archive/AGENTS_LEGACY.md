## 1. 제품의 고정 원칙

- 메디스캔노트는 **예비 보건의료인의 의료영상 학습을 지원하는 웹 서비스**다.
- AI 결과는 확정적 의료 진단, 처방, 진료 지시가 아니다. 사용자의 판단을 확인하고 학습을 보완하는 참고 정보로만 표현한다.
- 실제 환자의 개인정보가 포함된 자료와 비식별화되지 않은 의료데이터는 수집, 업로드, 저장, 학습, 테스트, 데모에 사용하지 않는다.
- 핵심 학습 루프는 `준비된 케이스 선택 -> 사용자 ROI 표시 -> 기준 ROI와 비교 -> 결과 및 해설 -> 오답노트 -> 동일 케이스 재도전`이다.
- MVP 대상 신체 부위는 뇌, 흉부, 복부, 무릎이다. 부위별 영상 종류와 질환은 아직 확정하지 않는다.
- 사용자 영상 AI 분석 흐름은 `비식별 영상 입력 또는 화면 공유 -> 관심 ROI 지정 -> AI 분석 -> 의심 영역·소견·후보 질환·관련 정보 확인`이며, 판독 훈련을 대체하지 않는 별도 학습 보조 흐름이다.
- 회원가입은 `계정 정보 -> 기본 정보 -> 이메일 인증`의 2단계 입력 흐름이다. 계정 정보는 이메일, 비밀번호, 비밀번호 확인, 약관 동의, `만 14세 이상` 확인이고 기본 정보는 중복 불가 닉네임, 필수 전공, 선택 입력인 가입 경로다. 전공은 `방사선학과·의학과/의예과·간호학과·기타 보건의료계열·비전공/해당 없음`을 제공한다. 학교·교육과정·현재 학년/상태와 별도 사용자 유형은 수집하지 않는다.
- 닉네임은 별도 중복 확인을 거쳐야 하며 수정하면 확인 상태를 초기화한다. 이메일 미인증 사용자는 로그인 세션을 시작할 수 있지만 이메일 인증·재발송·이메일 변경·로그아웃 외 핵심 학습 기능에는 접근할 수 없다. 화면 숨김만으로 처리하지 않고 서버/API 권한 검사에서도 차단한다.
- `[선택] 마케팅 정보 이메일 수신 동의`를 제공한다. 기본 선택하지 않고 거부해도 가입과 핵심 기능 이용에 영향을 주지 않는다. 필수 동의 문구는 `개인정보 수집 및 이용동의`로 표시한다.
- 이번 주 회원가입 산출물은 프론트엔드 화면단으로 제한한다. 실제 계정·동의 저장, 이메일·닉네임 중복 판정, 인증메일 발송·인증 완료는 구현하지 않고 데모 화면 상태로 구분하며 향후 백엔드 API에 연결한다.
- 전공은 추천할 학습 콘텐츠의 범위를 조정하는 신호로만 사용하고 학습 난이도를 직접 결정하지 않는다. 최초 학습 진입 시 사용자가 `처음 학습함`·`기초 이론을 학습함`·`실습 경험이 있음` 중 의료영상 학습 경험을 선택하고, 이후 실제 정답·부분정답·오답과 재도전 이력을 바탕으로 추천 난이도를 조정한다. 사용자는 추천과 무관하게 난이도를 직접 변경할 수 있어야 한다.
- 문제 난이도는 `입문`·`기초`·`심화`의 잠정 학습 난이도로 관리한다. 임상적 난이도라고 주장하지 않으며 실제 사용자 결과로 보정한다. 추천 전환에 필요한 문제 수·판정 조합·풀이시간 사용 여부와 임계값은 테스트 전까지 확정하지 않는다.
- 학교 교육, 임상실습, 의료전문가의 판단을 대체한다고 표현하지 않는다.

## 2. 문서 우선순위

원본 간 내용이 다를 때 다음 순서로 참고한다. 이 프로젝트에서 노션 Markdown은 **내부기획서**, PDF는 **산출물 기획서**라고 지칭한다. 모든 제품 기획과 개발 판단은 내부기획서를 근거로 한다. 산출물 기획서는 프로젝트 완료 후 제출할 중요한 공식 산출물이므로 내부기획과 계속 일치하도록 관리하되, 서로 다를 때 산출물 기획서가 내부기획을 덮어쓰지는 않는다.

1. `references/notion/서비스 기획 94fe589754308394af6a818f24c3b19a.md` - 2026-09-09 수정 **내부기획서**, 제품 기획의 기준
2. `references/notion/메디스캔노트_화면흐름도.png` - 내부기획서에 첨부된 최신 화면 흐름도
3. `프로젝트기획서_실전(기업2팀-김성일팀)- 피드백 수정용.pdf` - 프로젝트 완료 후 제출할 **산출물 기획서**. 내용은 내부기획과 맞춰 관리하며 굵게·밑줄 등 제출용 강조 서식을 포함
4. `references/화면흐름도.png` - 2026-08-27 저장된 이전 화면 흐름도

## 3. 상태 표기와 변경 규칙

- **확정**: 내부기획서와 사용자 지시가 일치하거나 사용자가 명시적으로 승인한 내용
- **제안**: 개발 가능성을 검토하기 위한 기준안이며 사용자 승인 전에는 확정이 아닌 내용
- **미확정**: 원본에서 결정되지 않았거나 구현 선택지가 여러 개인 내용
- **충돌**: 둘 이상의 원본이 서로 다르게 말하는 내용

작업자는 다음 규칙을 지킨다.

- 미확정 또는 충돌 상태를 코드, 데이터 스키마, API 계약으로 임의 고정하지 않는다.
- 범위나 정책을 바꾸기 전에 `docs/DECISIONS.md`를 갱신하고, 영향받는 문서를 함께 수정한다.
- 기능 이름은 "AI 진단" 대신 "AI 분석 정보", "의심 소견", "후보 질환", "학습 참고 정보"를 사용한다.
- ROI 채점은 준비된 기준 ROI와의 위치·겹침 비교다. 평가 공식과 임계값이 승인되기 전에는 특정 수치를 제품 규칙으로 간주하지 않는다.
- 현재 기획에는 교수자 검수 절차, 임상 성능 기준, 규제 분류가 확정되어 있지 않다. 관련 기능이나 표현은 승인 없이 추가하지 않는다.

## 4. 기술 스택 상태

내부기획서의 기술 섹션 자체가 "추후 확정"으로 표시되어 있으므로 아래 항목은 모두 **후보**다.

| 영역 | 현재 후보 | 상태/주의 |
| --- | --- | --- |
| 프론트엔드 | Vue.js | 미확정 |
| 백엔드/API | FastAPI | 미확정 |
| 관계형 DB | PostgreSQL | 미확정 |
| 프론트 배포 | Cloudflare Pages | 산출물 기획서에만 구체화, 미확정 |
| API·AI·DB 운영 | AWS | 서비스 구성과 비용 계획 미확정 |

## 5. 의료데이터 및 개인정보 규칙

- 닉네임을 사용해 실명 노출을 줄이더라도 계정이 익명화되는 것은 아니다. 이메일, 닉네임, 전공, 가입 경로, 약관 동의 기록, 접속 기록, 계정에 연결된 학습 경험·난이도 선택·학습·오답 이력은 서비스에서 개인을 식별하거나 구별할 수 있는 개인정보로 취급한다.
- 학교·교육과정·현재 학년/상태는 MVP 회원가입과 프로필에서 수집하지 않는다. 향후 실제 기능 목적이 생기기 전까지 다시 추가하지 않는다.
- 만 14세 미만 사용자는 MVP 가입 대상에서 제외한다. 생년월일을 추가 수집하지 않고 `만 14세 이상입니다` 필수 확인을 기본안으로 사용하되, 실제 공개 운영 전 연령 확인 방식과 약관 문구는 별도 검토한다.
- 공개 배포처의 교육·연구용 데이터라 하더라도 라이선스, 허용 목적, 재배포 조건, 비식별화 상태를 데이터셋별로 확인하고 기록한다.
- 환자 이름, 생년월일, 병원번호, 촬영기관·일시 등 재식별 단서가 픽셀 또는 메타데이터에 남아 있는 파일은 사용하지 않는다.
- DICOM을 다루게 될 경우 헤더 비식별화만으로 충분하다고 가정하지 말고 픽셀 내 번인 정보도 검사한다. 단, MVP의 DICOM 지원 여부는 미확정이다.
- 사용자 업로드·화면 공유 영상은 허용 형식, 전송 범위, 임시 보관, 영구 저장, 삭제 시점, 로그 포함 여부가 결정되기 전까지 영구 저장 기능을 구현하지 않는다.
- 데이터셋 원본, 사용자 영상, 모델 가중치, 비밀키를 Git에 커밋하지 않는다. 저장소에는 합성 또는 공개 사용이 명확히 허용된 최소 샘플만 둔다.
- 데이터 출처, 버전, 라이선스, 변환 이력, 라벨 출처, 학습/검증/테스트 분할을 추적할 수 있어야 한다.
- MVP의 기준 ROI와 병명은 우선 공개 데이터셋이 제공하는 기존 라벨을 사용한다. 의료전문가 검수 인력이 없으므로 이를 임상적으로 검증된 정답이라고 표현하지 않고, 데이터셋 제공 기준 라벨임을 기록·고지한다.

## 6. ROI 및 AI 작업 규칙

- 기준 ROI는 기존 오픈소스 데이터셋 제공 라벨을 우선 사용하며 라벨 출처와 원 데이터셋의 검수 정보를 기록한다.
- 현재 MVP에는 의료전문가 검수 인력이 없다. 기술적 무결성 검사는 수행하되 의료적 타당성 검증을 완료한 것처럼 표시하지 않는다.
- 정답·부분정답·오답 판정의 겹침 지표, 임계값, 다중 병변 처리, 빈 ROI 처리 방식은 승인 전까지 미확정이다.
- 산출물 기획서의 "약 40% 이상이면 부분정답"은 기능 테스트를 위한 초기 기준값이다. 테스트 결과에 따라 조정할 수 있으며 최종 고정 임계값으로 간주하지 않는다.
- 모델 성능은 단일 종합 수치만으로 보고하지 않고, 선정된 과제 유형에 맞춰 부위·질환·데이터 출처별 오류와 한계를 함께 기록한다. 구체 지표와 합격 기준은 미확정이다.
- AI 결과 화면에는 교육 목적, 비진단성, 오류 가능성, 입력 범위의 한계를 사용자가 이해할 수 있게 표시한다.
- AI가 생성한 문제, ROI 또는 해설을 기준 정답으로 쓰는 기능은 MVP 제외 항목이며, 향후 도입하더라도 사람의 검수 없이 게시하지 않는다.

## 7. 개발 착수 전 게이트

다음 항목이 `docs/DECISIONS.md`에서 결정되기 전에는 관련 구현을 시작하지 않는다.

- MVP 대상 네 부위별 영상 종류·질환 및 사용할 데이터셋
- ROI 기준 형식, 평가 지표, 임계값, 다중 병변 처리와 오답노트 완료 정책
