## 5. 미확정 사항

### 제품과 사용자 경험

- 최종 MVP에서 로그인·회원가입이 필수인지, 비회원 체험을 허용할지
- 확정된 전공 분류별 추천 콘텐츠 가중치
- 학습 경험과 실제 풀이 결과를 `입문·기초·심화` 추천에 연결할 문제 수·판정 조합·풀이시간 사용 여부와 임계값
- 이메일 인증 링크 만료·재발송 정책과 가입 후 닉네임 변경 정책
- 케이스 랜덤 시작 여부
- ROI 도형, 복수 ROI, 다중 병변·정상 케이스 처리
- 재도전 성공 후 오답노트 완료 처리와 이전 시도 보존 정책
- 재도전에서 이전 결과를 어떤 단위로 비교할지
- AI 결과를 학습 이력 또는 오답노트와 연결할지
- 사용성 검증 지표, 표본 수, 성공 기준

### 데이터와 AI

- 네 부위별 영상 종류, 질환, 최소 케이스 수와 데이터셋
- 원본 포맷, 웹 파생 포맷, ROI 및 라벨 포맷
- 의료전문가 추가 검수 부재 위험의 수용 여부와 데이터셋 제공 라벨의 신뢰 수준 고지 방식
- ROI 겹침 지표와 정답·부분정답 임계값
- AI 과제 유형, 모델, 프레임워크와 부위별 모델·어댑터의 실제 구성
- "후보 질환과 가능성"의 계산·표현 방식
- 모델 검증 지표, 외부 테스트, 합격 기준, 승인 주체
- 약 10,000개 및 10~15GB 목표의 실제 MVP 적합성

### 개인정보와 운영

- 계정 정보·기본 정보·동의 기록·학습 경험·추천 난이도·학습 이력별 보유 기간과 탈퇴 시 삭제 기준
- 사용자 파일·화면 공유의 허용 형식, 최대 크기와 화면 캡처 단위
- 비식별화 확인 절차와 위반 입력 차단 방식
- 입력·선택 ROI의 즉시 삭제 권장안 최종 승인, 결과·로그의 최소 보존 범위, 오류·시간초과·취소·백업 삭제 정책
- 사용자 입력을 개선·재학습에 사용할지 여부와 동의 방식
- 안전 고지 문구와 검수 책임자
- 보안, 인증, 권한, 감사 로그, 모니터링, 복구 목표

### 기술과 아키텍처

- 확정된 Vue CLI 구성에서 사용할 정확한 패키지 버전과 잠금 파일
- FastAPI, PostgreSQL 최종 채택 여부
- Cloudflare Pages, AWS, 화면 공유 중계의 최종 구조
- 객체 스토리지, 리전, 배포 단위, 비용 한도
- DICOM 지원 여부와 의료영상 뷰어 범위
- 동기/비동기 AI 추론 및 실패 처리 방식

| C-019 | 신규 확장 기능 시퀀스 | SRC-06의 독립 의학용어 사전, 비밀번호 찾기, 상세 마이페이지·통계·리포트는 현재 MVP 이후 항목이다. | 구현 대상이 아니라 참고 초안으로 보관. 범위 변경 시 PRD와 결정 원장을 먼저 갱신 |

## 7. 개발 전 사용자가 결정해야 할 질문

### P0 - 구현 구조를 바꾸는 필수 결정

1. **MVP 데이터 범위**: 확정된 뇌·흉부·복부·무릎 각각에서 지원할 영상 종류, 질환, 최소 케이스 수는 무엇입니까?
2. **데이터셋 채택**: 후보 중 어떤 데이터셋을 사용할 것이며 라이선스·비식별화·라벨 생성 과정을 누가 기술적으로 확인합니까?
3. **라벨 위험 수용**: 의료전문가 추가 검수 없이 데이터셋 제공 기준 ROI·병명·해설을 사용하는 위험을 MVP에서 수용하며, 화면에 어떤 고지 문구를 표시합니까?
4. **ROI 채점 규칙**: 어떤 겹침 지표와 임계값으로 정답·부분정답·오답을 구분합니까? 다중 병변과 큰 ROI는 어떻게 처리합니까?
5. **오답 완료 정책**: 재도전에서 정답으로 개선되면 완료 상태로 남깁니까, 목록에서 숨깁니까? 시도 이력은 몇 회 또는 얼마 동안 보존합니까?
6. **사용자 영상 처리**: 입력 파일 즉시 삭제 권장안을 최종 승인합니까? 결과·로그의 보존 범위와 실패·시간초과·취소·백업 삭제 규칙은 무엇입니까?
7. **AI 범위**: 네 부위 각각에서 어떤 영상 종류·질환을 대상으로 분류·탐지·분할 중 무엇을 수행하며, 부위별 모델/어댑터를 어떻게 라우팅합니까?
8. **AI 검증**: 의료전문가 검수자가 없는 조건에서 기술 성능의 합격 기준과 결과 문구의 승인 책임자는 누구입니까?

### P1 - MVP 화면·데이터 계약 결정

9. **향후 계정 구현**: 실제 계정 생성·이메일 발송을 연결할 때 사용할 인증 방식과 메일 서비스는 무엇입니까? 인증 링크 만료와 재발송 규칙은 무엇입니까?
10. **전공·난이도 추천 규칙**: 확정된 각 전공 분류의 추천 콘텐츠 범위는 무엇입니까? 세 학습 경험의 초기 난이도와 실제 결과에 따른 조정 규칙은 무엇입니까?
11. **지원 형식**: JPG/PNG만 지원합니까, DICOM 또는 다중 슬라이스/볼륨을 지원합니까?
12. **AI 결과 의미**: "후보 질환과 가능성"은 모델 확률, 점수, 순위 중 무엇이며 어떤 제한 문구로 표시합니까?
13. **화면 공유 단위**: 전체 화면을 연속 전송합니까, 사용자가 확정한 정지 캡처와 ROI만 전송합니까?
14. **재학습 비교 UI**: 이전 ROI, 현재 ROI, 판정, 겹침 수치 중 어떤 정보를 비교해 보여줍니까?
15. **서버·배포 기술**: FastAPI, PostgreSQL, Cloudflare Pages, AWS를 최종 채택합니까?
16. **스토리지·전송 구조**: 의료영상 객체 스토리지는 무엇이며 Cloudflare는 호스팅만 담당합니까, 화면 데이터 중계도 담당합니까?

### P2 - 일정과 확장성 결정

17. 개발 시작일은 2026-08-03과 2026-08-10 중 어느 날짜를 공식 일정으로 사용합니까?
18. 대시보드 최소 화면, 의학용어 사전, 통계·리포트 중 이번 MVP에 남길 항목이 있습니까?
19. 첫 사용자 검증은 방사선학과 고학년으로 한정합니까, 의과대학 등 다른 보건의료계열 학생도 포함합니까?
20. 관리자 페이지는 산출물 기획서 일정에 있으나 내부기획서의 기능 범위에는 없습니다. 이번 개발에서 완전히 제외해도 됩니까?

## 8. MVP 범위 상태

MVP의 최신 포함·제외 목록은 [PRD의 제안 MVP 범위](../product/PRD.md#3-제안-mvp-범위)와 [MVP 제외 범위](../product/PRD.md#7-mvp-제외-범위)가 기준이다. 이 문서에서는 범위를 다시 복사하지 않고, 범위를 바꾸는 확정 결정과 승인 대기 제안만 D·P 번호로 추적한다.

## 9. 결정 갱신 방법

사용자가 질문에 답하면 다음 형식으로 행을 추가한다.

| ID | 결정일 | 결정 | 근거/승인자 | 영향 문서 |
| --- | --- | --- | --- | --- |
| 예: D-015 | YYYY-MM-DD | 결정 내용 | 사용자 승인 | PRD, ARCHITECTURE, DATA_AI |

결정 후 해당 내용을 책임지는 [PRD](../product/PRD.md), [사용자 흐름](../product/USER_FLOW.md), [아키텍처](../system/ARCHITECTURE.md), [데이터·AI](../ai/DATA_AI.md) 등의 문서를 갱신한다. 충돌 행은 삭제하지 말고 `해결` 상태와 해결 근거를 덧붙인다.
