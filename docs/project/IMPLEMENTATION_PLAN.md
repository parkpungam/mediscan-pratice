# 메디스캔노트 MVP 구현 계획

## 1. 문서 안내

- **문서 역할:** 승인된 요구사항을 어떤 순서로 구현할지 큰 틀을 관리한다.
- **이 문서가 기준인 내용:** 권장 저장소 구조, 구현 순서 요약, 첫 사용자 흐름, 착수 제한
- **이 문서에 기록하지 않는 내용:** 기능별 상세 입력값, API 목록, 엔터티 필드, 테스트 케이스, 위험 원장
- **상태:** 사용자 승인 대기 중인 계획안
- **기준일:** 2026-09-14

내부기획서가 제품 기획의 우선 근거다. 산출물 기획서는 최종 제출 전 내부기획과 정합성을 확인한다. 이 계획을 승인받기 전에는 기능 구현, 패키지 설치, 애플리케이션 코드 생성을 시작하지 않는다.

이 문서에서는 다음 표기를 사용한다.

- **[확정]** 내부기획서 또는 사용자 답변으로 결정된 사항
- **[권장]** 일정과 위험을 고려한 구현 제안이며 승인 전에는 확정이 아닌 사항
- **[미확정]** 구현 계약에 영향을 주므로 개발 전에 선택이 필요한 사항

| 회원가입 기본 정보 | 중복 불가 필수 닉네임, 필수 전공, 선택 입력인 가입 경로, 별도 사용자 유형 없음 | 확정 |

## 3. 권장 저장소 및 폴더 구조

### 3.1 저장소 방식

**[권장] 하나의 저장소 안에서 웹, API, AI, 계약, 테스트를 분리하는 모노레포**를 사용한다. MVP 단계에서는 API 계약과 데이터 버전을 함께 바꾸기 쉽고, 네 부위의 공통 규칙을 한곳에서 추적할 수 있기 때문이다. 실제 폴더 생성은 계획 승인 후에 한다.

```text
/
├─ docs/
│  └─ README.md               # 현재 문서 구조와 책임 안내
├─ references/                 # 원본 기획자료, 애플리케이션에서 직접 참조하지 않음
├─ frontend/                   # PC 웹 UI
│  ├─ public/
│  ├─ src/
│  │  ├─ assets/               # 이미지와 공통 CSS
│  │  ├─ components/common/    # 공통 입력창·버튼
│  │  ├─ components/signup/    # 회원가입 단계별 컴포넌트
│  │  ├─ views/                # Router에 연결되는 큰 화면
│  │  ├─ router/               # Vue Router 설정
│  │  ├─ constants/            # 전공·가입 경로 등 고정 선택지
│  │  ├─ utils/                # 입력값 검증 함수
│  │  ├─ services/             # 향후 백엔드 API 연결 경계
│  │  ├─ App.vue
│  │  └─ main.js
│  ├─ tests/
│  ├─ package.json
│  ├─ babel.config.js
│  ├─ jsconfig.json
│  └─ vue.config.js
├─ backend/                    # 인증·학습·평가·오답·AI 조정 API
│  ├─ app/api/
│  ├─ app/domain/
│  ├─ app/services/
│  ├─ app/repositories/
│  ├─ app/db/
│  ├─ app/security/
│  └─ tests/
├─ ai/                         # 제품 API와 분리된 분석 경계
│  ├─ src/common/
│  ├─ src/routing/
│  ├─ src/brain/
│  ├─ src/chest/
│  ├─ src/abdomen/
│  ├─ src/knee/
│  ├─ src/evaluation/
│  └─ tests/
├─ contracts/                  # OpenAPI, 데이터 스키마, 오류 코드, 예시 응답
├─ data/
│  ├─ catalog/                 # 출처·버전·라이선스·해시·검수 수준 메타데이터
│  ├─ schemas/                 # 케이스·ROI 교환 형식
│  ├─ samples/                 # 합성 또는 재배포 허용이 명확한 최소 샘플만
│  └─ README.md
├─ tests/e2e/                  # 핵심 사용자 흐름 종단 테스트
└─ infra/                      # 배포 대상이 확정된 뒤 환경별 설정
```

원본 의료영상, 사용자 업로드, 모델 가중치, 비밀키는 Git에 두지 않는다. 공개 데이터셋도 라이선스가 재배포를 명시적으로 허용하지 않으면 저장소에는 내려받기 절차와 카탈로그만 둔다.

## 4. 영역별 책임과 경계

프론트엔드, 백엔드, 데이터베이스, 스토리지와 AI의 책임 및 금지 경계는 [ARCHITECTURE의 구성요소별 책임](../system/ARCHITECTURE.md#4-구성요소별-책임)을 따른다. 구현 계획에는 그 내용을 반복하지 않고 단계와 완료 조건만 기록한다.

## 5. 가장 먼저 구현할 핵심 사용자 흐름

일정상 첫 산출물과 제품상 첫 종단 흐름을 구분한다.

### 5.1 이번 주 첫 산출물

`1/2 계정 정보 → 2/2 기본 정보 → 가입 제출 시연 → 인증 메일 발송 안내 상태`

- **[확정]** 이번 주에는 로그인 화면이 아니라 회원가입 화면단을 구성한다.
- **[확정]** 1단계는 이메일, 비밀번호, 비밀번호 확인, 약관 동의, 만 14세 이상 확인이다. 생년월일은 기본 수집하지 않는다.
- **[확정]** 2단계는 필수 닉네임, 필수 전공, 선택 입력인 가입 경로이며 별도 사용자 유형은 받지 않는다. 학교·교육과정·현재 학년/상태는 받지 않는다. 전공은 선택 목록과 `기타 직접 입력`·`비전공/해당 없음`을 제공한다.
- **[확정]** 미인증 사용자도 로그인할 수 있지만 인증·재발송·이메일 변경·로그아웃 외 핵심 기능은 프론트와 서버/API 양쪽에서 차단한다.
- **[확정]** 이번 주에는 실제 계정·동의 저장, 이메일·닉네임 중복 판정과 인증 메일 발송을 연결하지 않고 화면 상태만 구현한다. 시연 시 실제 가입이나 메일 발송으로 오해되지 않게 표시한다.
- **[향후]** 백엔드를 연결할 때 현재 폼의 제출 함수를 등록 API 호출로 교체하고 이메일·닉네임 중복 검사, 비밀번호 해시, 약관 버전 기록, 인증 링크 보안을 추가한다.

### 5.2 첫 제품 종단 슬라이스

`로그인 → 최초 학습 경험 선택 → 추천 난이도 확인/직접 변경 → 신체 부위 선택 → 케이스 선택 → 기준 ROI를 숨긴 영상 확인 → 사용자 ROI 제출 → 정답/부분정답/오답 판정 → 기준 ROI·해설 확인 → 부분정답/오답 자동 저장 → 추천 난이도 갱신 → 동일 케이스 재도전 → 이전 결과 비교`

이 흐름을 AI 모델 개발보다 먼저 완성한다. ROI 판독 훈련의 채점은 준비된 기준 ROI와의 기하학적 비교이므로 사용자 영상 AI 모델이 없어도 독립적으로 검증할 수 있다.

## 9. MVP 이후로 미룰 기능

최신 제외 목록은 [PRD의 MVP 제외 범위](../product/PRD.md#7-mvp-제외-범위)가 기준이다. 대표적으로 상세 통계·리포트, 독립 의학용어 사전, 계정 복구·상세 설정, 교수자·관리자 기능, PACS/DICOM 관리 플랫폼, 결제, 사용자 영상 영구 보관, 범용 AI 분석을 이후로 미룬다.

## 10. 승인 후 착수 원칙

계획 승인은 폴더 구조, 구현 순서, 완료 조건에 대한 승인으로 본다. 기술 스택과 P0 항목은 승인된 것만 구현 계약으로 전환한다. 사용자가 계획을 검토하고 명시적으로 구현 시작을 요청할 때까지 코드·패키지·애플리케이션 폴더는 만들지 않는다.
