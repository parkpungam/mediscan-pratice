# 메디스캔노트 단계별 작업 및 완료 조건

## 1. 문서 안내

- **문서 역할:** 구현 계획에 정의된 각 단계의 작업과 완료 조건을 상세히 관리한다.
- **이 문서가 기준인 내용:** 단계 0~5의 상세 작업, 검증 기준, 다음 단계 진입 조건
- **이 문서에 기록하지 않는 내용:** 전체 일정 요약, 저장소 구조, 기능별 입력 규칙, API·데이터 필드 상세
- **상태:** 사용자 승인 대기 중인 계획안
- **기준일:** 2026-09-14

전체 구현 순서와 폴더 구조는 [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)를 따른다. 입력·API·데이터·테스트의 세부 규칙은 각 단계에서 연결한 담당 기준 문서를 확인한다.

## 2. 단계 0. 승인과 계약 고정

### 작업

- 구현 계획 승인
- 네 부위별 데이터셋·영상 종류·질환·최소 케이스 수 결정
- ROI 좌표 형식, 비교 지표, 잠정 임계값과 버전 관리 방식 결정
- 확정된 전공 분류별 추천 콘텐츠 범위 결정
- 세 학습 경험과 초기 난이도의 연결, 추천 갱신 전 최소 문제 수, 판정별 가중치, 풀이시간 사용 여부와 단계 전환 기준 결정
- 사용자 입력 삭제 및 AI 과제의 P0 정책 결정

### 완료 조건

- [DECISIONS.md](./DECISIONS.md)에 P0 결정이 기록되어 있다.
- API와 데이터 스키마 초안이 승인되어 화면이 기준 ROI를 제출 전에 노출하지 않는다.
- 데이터셋별 출처·라이선스·비식별화·원 라벨 생성 정보를 확인할 담당자가 정해져 있다.

## 3. 단계 1. 이번 주 2단계 회원가입 UI

### 작업

- [SIGN_UP.md](../product/features/SIGN_UP.md)에 정한 2단계 화면과 모든 입력·검증·오류 상태 구성
- 인증메일 발송 안내와 재발송·이메일 변경의 화면 상태 구성
- 중복 확인, 가입, 메일 발송은 데모 상태로 표현하고 실제 API는 연결하지 않음

### 완료 조건

- `SIGN_UP.md`의 입력·검증·화면 이동 조건을 모두 만족한다.
- `계정 정보 → 기본 정보 → 인증메일 발송 안내`가 끊김 없이 재현된다.
- 데모 동작과 실제 서버 동작을 관람자가 구분할 수 있다.
- 입력값을 화면 상태 밖에 영구 저장하지 않고 비밀번호를 로그·URL·브라우저 영구 저장소에 남기지 않는다.

## 4. 단계 2. ROI 판독 훈련 한 케이스 종단 슬라이스

### 작업

- 최초 학습 경험 선택, 잠정 난이도 추천과 사용자 직접 변경
- 승인된 한 케이스로 영상 표시, ROI 작성·수정·삭제·제출
- 서버의 정규화 좌표 검증과 기준 ROI 비교
- 세 가지 판정, 기준 ROI 오버레이, 병명·소견·용어·참고자료 표시

### 완료 조건

- 제출 전 API와 브라우저 상태에서 기준 ROI·정답 라벨이 노출되지 않는다.
- 동일 입력은 동일 평가 규칙 버전에서 동일 결과를 낸다.
- 초기 추천 난이도의 근거가 학습 경험임을 표시하고 사용자가 다른 난이도를 선택할 수 있다.
- 빈 ROI, 범위 밖 좌표, 너무 큰 ROI, 경계값, 이미지 크기 변화 테스트가 통과한다.
- 약 40%는 테스트용 초기값으로만 표시되고 데이터 수정 없이 평가 규칙 버전을 바꿀 수 있다.

## 5. 단계 3. 네 부위 케이스와 오답 재학습

### 작업

- 뇌·흉부·복부·무릎 각각의 승인된 최소 케이스 카탈로그 연결
- 부분정답·오답 자동 저장, 목록·상세·재도전, 이전/현재 결과 비교
- 정답·부분정답·오답과 재도전 이력을 승인된 규칙 버전에 입력해 다음 추천 난이도 갱신
- 데이터 출처·버전·라이선스·추가 의료 검수 없음 표시

### 완료 조건

- 네 부위 모두 최소 한 개 이상의 승인된 케이스가 전체 학습 루프를 완료한다. 실제 최소 수량은 단계 0에서 별도 승인한다.
- 부분정답과 오답은 중복 항목을 무제한 생성하지 않고 시도 이력과 연결된다.
- 재도전은 기준 ROI를 다시 숨긴 상태에서 시작하며 이전 결과를 식별 가능하게 비교한다.
- 추천 난이도는 같은 입력 이력과 규칙 버전에서 재현되며, 사용자가 선택한 난이도를 덮어쓰지 않는다.
- 깨진 파일, 누락 라벨, 좌표 불일치, 중복 데이터 검사가 통과한다.

## 6. 단계 4. 사용자 영상 AI 분석의 제한된 종단 슬라이스

### 작업

- 비식별화 고지·동의, 허용 파일 또는 승인된 정지 캡처, 관심 ROI 지정
- 명시적 부위 선택, 지원 범위 검사, 부위별 모델/어댑터 호출
- 선택 원본 영역, 의심 영역, 주요 소견, 후보 정보, 관련 정보와 비진단성 안내
- 입력 즉시 삭제 권장안이 승인된 경우 격리 임시 저장과 삭제 처리

### 완료 조건

- 지원하지 않는 부위·영상 종류·형식은 추론 전에 명확히 거절한다.
- 성공, 분석 실패, 시간초과, 사용자 취소에서 임시 입력 삭제가 자동 검증된다.
- 사용자 원본이 애플리케이션 로그, 오류 추적, 백업, 모델 재학습 데이터에 남지 않는다.
- 출력에는 모델·데이터 버전과 한계가 연결되고 진단·치료 표현이 없다.
- 의료전문가 검수 부재로 인해 이 평가는 기술적 성능 검증이며 임상 검증이 아님을 표시한다.

## 7. 단계 5. 통합 검증과 최종발표 준비

### 작업

- 핵심 두 흐름의 종단 테스트, 접근성·반응형·오류 복구 점검
- 개인정보·데이터 라이선스·삭제·정답 누출 점검
- 데이터 및 모델 평가 보고, 알려진 한계와 데모 운영 절차 정리
- 내부기획과 산출물 기획서의 최종 정합성 확인

### 완료 조건

- 2026년 12월 11일 최종발표 시나리오가 배포 환경에서 재현된다.
- 치명·높음 위험의 미해결 결함이 없고, 남은 제한은 화면과 문서에 기록되어 있다.
- 승인된 브라우저와 성능 기준을 통과한다. 구체 브라우저·응답시간 기준은 단계 0 또는 개발 중 별도 결정한다.
- 배포본의 케이스, 평가 규칙, 모델, 데이터 출처 버전을 재현할 수 있다.
